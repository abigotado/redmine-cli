# redmine-cli v0.1.1

This patch release makes local validation and transient Redmine failures more
predictable for automated callers without changing the v1 JSON envelope or
the read-only command surface.

Fixes:

- `issues list` validates its filters and malformed pagination cursors before
  loading a profile or reading the macOS Keychain;
- unknown profile names no longer create permanent per-profile lock files;
- the selected profile is refreshed while locked before its credential is
  loaded, preventing a concurrent profile update from pairing a token with a
  stale Redmine URL;
- a `429 Too Many Requests` response keeps `RATE_LIMITED` and `retry_after`
  when the advertised delay exceeds the remaining command deadline;
- oversized numeric `Retry-After` values saturate safely instead of wrapping
  into a negative duration;
- draft GitHub releases are resolved and published by numeric release ID during
  final verification;
- Homebrew builds use corrected source-version detection and module archive
  roots when staging checksum-pinned resources with networking disabled.

The fixed skill-installer coordination lock intentionally remains in the
skills root after uninstall. It is a single stable advisory-lock inode shared
by concurrent install and uninstall processes; removing it would allow two
processes to lock different inodes and overlap filesystem mutations.

This release remains source-only. It does not add write commands, change the
credential storage boundary, or publish unsigned macOS binaries.
